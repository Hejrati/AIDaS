Deeper-layer variant verification

Original and Optimized retain their existing six-boundary outputs; Optimized
remains the default. The optional Optimized deeper layers choice uses:

  RAW_OCT_PROCESSING_2023_09SEP-05_WSU_optimized_deep_layers.R
  more_outputs_afterRAW_OCT_PROCESSING_2022_11NOV_27_WSU_noHypoDenseBand_EA edited_optimized_deep_layers.R

AIDaS sets AIDAS_STEP3_DEEP_ONLY=1 for the selected new main script and requires
the matching new output script. Standalone execution defaults to full processing
with AIDAS_STEP3_DEEP_ONLY unset or 0; set it to 1 for deeper-layer processing.
The companion follows the deep_layers_only mode saved in the loaded workspace.

Run the unchanged optimized baseline, the new main script with the switch off,
and the new main script with the switch on in fresh R sessions and separate
output folders. Keep all six markings, indexes, pixel width, R packages, and
worker count identical; start with AIDAS_STEP3_WORKERS=1. Use several distinct
acquisitions or markings. Original and optimized scripts must remain untouched.

Compare the saved unrounded results with the production R executable:

  Rscript.exe --vanilla release_tools/verify_step3_deep_layers.R BASELINE_DONE_RDATA CANDIDATE_DONE_RDATA full
  Rscript.exe --vanilla release_tools/verify_step3_deep_layers.R BASELINE_DONE_RDATA CANDIDATE_DONE_RDATA deep

Replace the two workspace arguments with their actual _done_...RData paths.
Full mode compares the existing numerical outputs without omitting any boundary.
Deep mode requires exact retained RPE, OLM, ONL/OPL, INL/IPL, internal surface,
deeper samples/profiles, and foveal results. It also checks the original array
layout and missing-value masks. A mismatch must be investigated, not tolerated.
The numerical arrays keep 90 depth positions: columns 35:90 are retained and
columns 1:34 are missing in deeper-layer mode. The eight-column thickness tables
retain the original labels and positions, with unwanted measurements marked NA.
Normalized Analyze images can zero-fill omitted depths for display; use the
workspace rather than those zero-filled regions as the numerical reference.
Masking omitted table values can also change R's text formatting and rounding.
Compare unrounded workspace values exactly, and validate the deep text table
against the unchanged formulas with the missing-value mask applied.

App runtime optimization and elapsed timing

Matching bundled Optimized and Optimized deeper layers pairs set
AIDAS_STEP3_DEFER_BORDER_PLOTS=1 and AIDAS_STEP3_RASTER=1. The main script skips
only its duplicate final border PNGs; the companion supplies the final previews.
This changes grayscale PNG resampling, not scientific arrays or border positions.
Standalone defaults and custom script behavior are preserved. Optimized scripts
have no binary-array export code and discard implicit graphics through a null
device, so new runs produce neither step3_r_arrays nor Rplots.pdf.
The app measures elapsed wall-clock time with a monotonic clock, updates once
per second, and retains the final total for completion/failure/cancellation.
Historical files from older runs are not regenerated by current scripts.

  Rscript.exe --vanilla tests/r/step3_runtime_artifacts.R
  python -m unittest tests.steps.step3.test_step3_elapsed_timer tests.steps.step3.test_step3_preview_pipeline

Strict file-byte verification for the existing original and optimized scripts

Run from the checkout using Windows PowerShell:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File release_tools/verify_step3_r_outputs.ps1 -BaselineScript RAW_OCT_PROCESSING_2023_09SEP-05_WSU.R -CandidateScript RAW_OCT_PROCESSING_2023_09SEP-05_WSU_optimized.R -FixtureDirectory "Examples/R_TEST/flip human" -WorkDirectory debug_outputs/r_optimization_validation/harness

The default fixture configuration expects Light and Light_MARKED Analyze pairs
with two slices. Set -ImageIndex "1,2,3" for a three-slice fixture, -PixelWidth
for another acquisition scale, and -Rscript/-RLibrary for another R installation.
The legacy script's single-slice behavior is intentionally preserved.

The harness copies inputs into its own work directory and runs both versions
at identical paths with identical arguments. It compares every exported file
directly, without numerical tolerance, and records SHA256 hashes, timing, and
the first differing byte. This includes both saved R workspaces. The same paths
are necessary because INPUTDIR, OUTDIR, PYEXPORTDIR, and args are saved objects.

All generated artifacts are retained under snapshots; manifests and comparisons
are JSON files in the work directory. Existing acquisition files are not changed.
Use -Phase baseline, candidate, or compare to execute one step at a time. An
optional -RepeatBaseline checks whether the original produces reproducible bytes.

To validate the optional parallel lateral search after the default comparison:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File release_tools/verify_step3_r_outputs.ps1 -BaselineScript RAW_OCT_PROCESSING_2023_09SEP-05_WSU.R -CandidateScript RAW_OCT_PROCESSING_2023_09SEP-05_WSU_optimized.R -FixtureDirectory "Examples/R_TEST/flip human" -WorkDirectory debug_outputs/r_optimization_validation/harness -Phase candidate -CandidateName candidate2 -Workers 2

Repeat with -Phase compare -CandidateName candidate2 to compare that snapshot.
The processing script defaults to one worker. Set AIDAS_STEP3_WORKERS=2 to use
two workers outside the harness; no additional R packages are required.

R 3.3.1 writes wall-clock CreationDate and ModDate fields in the automatic
input/Rplots.pdf. Even unchanged runs can differ in those fields. The harness
reports raw PDF inequality and separately diagnoses timestamp-only differences;
it never excludes or normalizes an artifact to make the strict check pass.
The analysis-output comparison count is reported separately from that PDF.

Run the focused regression suites with the production Rscript executable:

  Rscript.exe --vanilla tests/r/step3_optimization_kernels.R
  Rscript.exe --vanilla tests/r/step3_lateral_registration.R
  Rscript.exe --vanilla tests/r/step3_deep_layers.R

These cover byte-exact sampling, mean arithmetic, correlation, depth lookup,
factor alignment, spline prediction, workspace cleanup, and parallel/RNG state.
